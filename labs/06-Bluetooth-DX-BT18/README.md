# LAB-06 — DX-BT18 / BT18-compatible Bluetooth UART module

**Если у вас ещё не установлен Git**, откройте PowerShell в Windows 10/11:

```powershell
winget install --id Git.Git -e --source winget
```

Закройте и снова откройте PowerShell, затем проверьте:

```powershell
git --version
```

Если `winget` недоступен, скачайте Git с официального сайта:
https://git-scm.com/install/windows

**Если Git уже установлен**, ничего переустанавливать не нужно. Скачайте наш действующий репозиторий:

```powershell
New-Item -ItemType Directory -Force C:\\GitHub | Out-Null
Set-Location C:\\GitHub
git clone https://github.com/AIDevelopersMonster/Arduino-UNO-Shields.git
Set-Location .\\Arduino-UNO-Shields
```

Если этот репозиторий уже существует на компьютере:

```powershell
Set-Location C:\\GitHub\\Arduino-UNO-Shields
git pull --ff-only
```

Эти действия не требуют GitHub-токена: репозиторий публичный. Все дальнейшие обновления скриптов и руководств будут появляться в GitHub, повторно вставлять код из переписки не нужно.

## 0. Быстрый запуск лаборатории (PowerShell)

Нужны Python 3.10+ и Bluetooth-адаптер компьютера для BLE-теста. Проверить Python:

```powershell
py --version
```

Если Python отсутствует, установите его с https://www.python.org/downloads/windows/ и откройте новый PowerShell. Из корня клонированного репозитория:

```powershell
py -m venv .venv
.\\.venv\\Scripts\\python.exe -m pip install -r .\\tools\\bt18\\requirements.txt
.\\.venv\\Scripts\\python.exe .\\tools\\bt18\\bt18_probe.py --list-ports
```

Подключите модуль через адаптер USB-UART с логическими уровнями **3,3 В**. Подставьте фактический COM-порт (пример `COM4`):

```powershell
.\\.venv\\Scripts\\python.exe .\\tools\\bt18\\bt18_probe.py --port COM4 --baud 9600 --profile dual
```

Если у вас BLE-only вариант или dual-mode не отвечает, разрешён второй профиль *чтения*:

```powershell
.\\.venv\\Scripts\\python.exe .\\tools\\bt18\\bt18_probe.py --port COM4 --baud 9600 --profile le
```

BLE-поиск с ПК:

```powershell
.\\.venv\\Scripts\\python.exe .\\tools\\bt18\\bt18_ble_scan.py --duration 10 --name BT18
```

Не используйте `--name BT18`, если устройство может рекламироваться под неизвестным именем: выполните полный поиск без фильтра.

После сканирования для **конкретного** найденного BLE-идентификатора можно получить карту GATT:

```powershell
.\\.venv\\Scripts\\python.exe .\\tools\\bt18\\bt18_ble_scan.py --address "DEVICE_ID_FROM_SCAN"
```

Этот шаг устанавливает BLE-соединение для перечисления сервисов. Он не записывает характеристики и не прошивает модуль. BLE-сканирование **не** проверяет Classic Bluetooth/SPP.

Подробные параметры скриптов: [tools/bt18](../../tools/bt18/README.md).

## 1. Объект исследования и ограничения

- Покупка: модуль под названием DX-BT18 без маркировки на металлическом RF-экране.
- Аппаратный производитель и SoC **не установлены**.
- Оригинальная DX-SMART документация — справочник для сравнения, **не сертификат** нашей платы.
- Номинально DX-BT18 — Bluetooth 4.2 Classic SPP + BLE UART; существует другая ветвь BT18-LE (BLE-only).
- **Статус LAB-06: PENDING HARDWARE TEST.** Ни одного PASS на конкретном экземпляре пока не зафиксировано.

Две независимые группы свидетельств: (а) ответы AT по UART и (б) фактическая BLE-реклама/GATT. Совпадающие имена, UUID или версия AT **не подтверждают** оригинальность чипа.

## 2. Соединение без риска для клона

```text
USB-UART 3.3 V logic       BT18 MODULE (signals must be confirmed)
TX ---------------------> RX
RX <--------------------- TX
GND -------------------- GND
3.3 V regulated -------- VCC (bare module only)
```

- Не подавать 5 В на UART RX или VCC **голого радиомодуля**. Некоторые платы-переходники имеют собственный стабилизатор, но это надо подтверждать по плате.
- Не подключать к неизвестным контактам `ICE`, `VPP`, `KEY` или `P26` по одной лишь похожей надписи/внешности.
- По руководству **оригинального dual-mode DX-BT18** контакт модуля **P26 (GPIO25)** должен быть LOW для AT-режима; **BT18-LE** не требует этого. Числа относятся к контактам 33-позиционного радиомодуля, а не к пинам переходной платы.
- Старт: UART **9600, 8N1, без аппаратного flow control**; команды завершать `CRLF`.
- Освободите COM-порт (закройте Serial Monitor/другие клиенты). На время AT-проверки желательно отключить Bluetooth-подключения.
- Отсутствие ответа при неверном режиме AT **не равно неисправности** модуля.

| TEST-02 | BLE advertising, фактическое имя, сервисы/характеристики GATT | PENDING |

## 4. Доступные «регистры» и прошивка

Документированные AT-команды работают с логическими конфигурационными полями. Это **не регистры памяти SoC**. BLE GATT-характеристики — также не адреса физических регистров.

Оригинальное руководство обозначает **P8/ICE** как порт обновления firmware и **P7/VPP**. Оно не предоставляет проверенного открытого комплекта «firmware + programmer + процедура восстановления» для нашего неидентифицированного образца. Команды для чтения/записи произвольных адресов RAM, FLASH, OTP, периферии в AT-руководстве отсутствуют.

**Перепрошивка отложена**, пока не установлены SoC, назначение контактов, тип памяти, совместимый софт и способ восстановления. Не подавать экспериментальные напряжения на ICE/VPP.

Отдельные решения на YiChip YC1021 используют внешнюю EEPROM для конфигурации, но **карта EEPROM из сторонней платы не является картой DX-BT18**. Даже если будут совпадения в сигналах, не приравнивать без измерений кристалл DX1022 к YC1021.

## 5. GitHub-first порядок для читателей и автора

1. Исправления кодов и инструкций вносятся в этот GitHub-репозиторий.
2. Читатель выполняет `git pull --ff-only`, затем запускает нужный тест.
3. Консольные результаты/снимки измерений передаются отдельно и заносятся в `RESULT_YYYY-MM-DD.md` **только при наличии фактических данных**.
4. Различать `PASS`, `PARTIAL`, `FAIL`, `PENDING`; не выдавать гипотезы об идентичности за подтверждённое происхождение.
5. После 2–3 осмысленных проверок при отсутствии прогресса фиксировать ограничения и прекращать работу с конкретным экземпляром без бессрочного «ремонта».

Личные дампы могут содержать MAC-адреса окружающих устройств. Не публикуйте их без очистки. Локальные `results/` исключены из Git.
