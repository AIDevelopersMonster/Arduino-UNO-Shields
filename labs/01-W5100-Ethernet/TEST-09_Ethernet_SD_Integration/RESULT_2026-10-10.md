The primary failure is CARD_INIT. In SD 1.3.0, code 1 means CMD0 did not return
the required idle response before its initialization timeout; 255 is the
last response status FF. Its physical cause is not established. The same
error had occurred in TEST-08, which later passed after complete power-off
and reported a subsequent ordinary-repeat PASS. That history suggests the
next controlled diagnostic, without proving an identical cause here.

This firmware stops before root opening, exclusive creation, DHCP or UDP
binding when CARD_INIT fails. **No T09CHECK.BIN was created by this run.**
The generic host warning about a possible leftover file does not establish
that such a file exists. Formatting or deleting files is not needed for this
early initialization failure.

The additional host reasons are unfulfilled acceptance gates after the early
abort. In particular, sampled RAM gate failed because the initial reference
was not populated; the shown minimum 531 B itself is above the 512 B limit.
This is not a completed memory test under load. The RTR gate cannot compare
against an unestablished reference; two reads of 07D0 do not indicate RTR
corruption. elapsed_ms=0 refers to the unstarted load, not an instantaneous
SD initialization failure or proof that 60 s elapsed.
