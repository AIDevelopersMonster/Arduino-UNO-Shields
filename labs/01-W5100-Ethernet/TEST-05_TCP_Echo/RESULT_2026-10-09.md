# TEST-05 — TCP Echo Server and PowerShell Client: FULL PASS

Date: 2026-10-09. Arduino UNO + blue WIZnet W5100 Ethernet Shield; microSD absent. Serial Monitor and PowerShell client logs submitted by user. This verdict applies to the specified bounded protocol only.

## Hardware startup

```text
KON W5100 TEST-05 / TCP ECHO / SD OFF
DHCP request...
Controller: W5100
IP: 192.168.1.83
TCP_PORT: 5000
SERVER STARTED / TCP TEST PENDING
```

## Arduino serial observations

- Connections #1 through #20: `TCP ECHO #1` through `TCP ECHO #20`, each `bytes=11`, each closed; rejected count 0.
- Connection #21: `TCP ECHO #21 bytes=64`, then closed, rejected count 0.
- Connection #22: `TCP ERROR: incomplete or timed-out line`, connection closed; rejected count becomes 1 (deliberate incomplete transfer).
- Connection #23: `TCP ECHO #22 bytes=12`; success after the aborted session.
- Final Arduino counters: `TCP CLOSE / echo=22 rejected=1`.

## PowerShell client observations

```text
TEST-05 / TCP Echo / IP=192.168.1.83 Port=5000 Count=20
PASS session 1 : KON-TCP-001
...
PASS session 20 : KON-TCP-020
PASS 64-byte boundary
INFO aborted incomplete connection
PASS reconnect after abort
RESULT: PASS / verified=22, failures=0
```

The host client compares each returned ASCII echo exactly, including the 64-byte boundary message and post-abort reconnect. 20 + 1 + 1 = 22 verified Echo responses; 23 total connections includes one deliberately rejected incomplete request.

## Verdict

**FULL PASS** for the declared TEST-05 protocol: 20 independent TCP echo sessions, exact response integrity for these payloads, 64-byte message, expected rejection of incomplete request and successful connection after abort. No unexpected failure observed.

**Not claimed:** W5100 performance under concurrent clients, high throughput, multi-hour or multi-day soak, Ethernet cable disconnect/recovery, TLS/authentication, outbound TCP client on the UNO or microSD functions.
