# TEST-09D — Manual SPI Arbitration: observed bench result

**Date:** 2026-10-11  
**Hardware:** Arduino UNO + blue W5100 Ethernet Shield with microSD  
**Result:** **PARTIAL PASS / SWITCHING FAIL** (both peripheral subsystems operate alone; sequential mode switching fails in this configuration).

## Commands and actual evidence

### SD first, then LAN
- Boot: `SD=OFF LAN=OFF D4=HIGH D10=HIGH`.
- `S1`: `SD CONNECTED PASS`, `WRITE PASS / FILE CLOSED`, `READ VERIFY PASS / FILE CLOSED`, `SD PASS`.
- `S0`: SD deselected, `D4 HIGH`, `LAN OFF`.
- `L1`: prints `DHCP REQUEST (UP TO ~10S)...` the operator waited without seeing completion, then **manually restarted the program**. **No `L1 PASS` and no `L1 FAIL` were captured before that action.** This does not show a spontaneous reset.

### LAN first, then SD
- After the operator's restart, `L1`: LAN PASS, DHCP IP `192.168.1.75`, UDP Echo port 5003 ready. A UDP packet transmission was not shown in this log; DHCP+UDP bind PASS only.
- `L0`: UDP stopped, W5100 D10 HIGH, both modes OFF.
- `S1`: `SD.begin(4)` FAIL, both modes remain OFF; no file operation occurred.

## Background controls

- TEST-09C standalone SD successfully initialized the card, wrote K09C.TXT, reopened it and verified every byte: FULL PASS.
- Earlier TEST-07 Ethernet tests validated DHCP/UDP and cable recovery without active SD operations.
- TEST-07C SD.h-only (no SD operations) had working Ethernet.
- TEST-09B integrated run: no UDP echo/no report; follow-up TEST-09B DIAG found SD FAIL / Ethernet PASS / IP 192.168.1.73.

## Evidence boundaries

`D4=HIGH` and `D10=HIGH` are static readings reported after library calls; they do not establish chip-select timing during SPI transfers nor MISO tri-state behavior. S0/L0 are logical deselection only, not hardware power cycling. The program was restarted by the operator after waiting for DHCP. There is no evidence of spontaneous reset; the DHCP wait duration and underlying cause remain unmeasured.

**Conclusion:** Two transition symptoms were observed: DHCP did not visibly finish before manual restart after SD-to-LAN, and SD.begin(4) failed after LAN-to-SD. Shared-SPI arbitration / library lifecycle / electrical interaction remains unresolved. No general conclusion that all W5100 Shields cannot share SPI with SD.

**Lab decision:** This is the final bounded experiment of this subprogram. Preserve findings; do not iterate hardware repair or speculative firmware patches without a new explicit objective.
