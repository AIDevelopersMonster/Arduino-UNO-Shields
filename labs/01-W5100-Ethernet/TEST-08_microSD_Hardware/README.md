# TEST-08 — microSD hardware / Arduino UNO + W5100

**v0.4: два аппаратных ETH_SPI_BEFORE FAIL после CARD_INIT PASS.**
`E272AB07`: RTR=0750, затем 07D0. `DDA2F317`, после предложенной замены карты:
RTR=FFFF оба раза. Пробной записи и файловых операций не было.
Отдельная [проверка через USB-картридер / Windows](USB_SD_CHECK.md) прошла:
16 MiB, побайтовое сравнение и SHA-256 до/после переподключения (`82E149BC65C6`).
[UNO SD_ONLY](diagnostics/SD_Only/) фактически прошёл все 13 SD/file проверок
без программных обращений к W5100 (`B652B736`, min_free=938 B, 443 ms).
Следующий шаг — [W5100_COMPARE](diagnostics/W5100_Compare/): сравнение raw и
драйверного RTR на 4 МГц вокруг SD-операций; аппаратный результат PENDING.
Полная прошивка TEST-08 v0.4 и её критерии не изменены.
Предыдущая v0.3 завершилась CARD_INIT FAIL (`D39AF82E`).
По указанию оператора подбор частоты/условий питания остановлен; выполнен
[аудит алгоритма](../SPI_ORDER_AUDIT_2026-10-10.md). v0.4 предварительно задаёт
CS=HIGH до OUTPUT, инициализирует SD первой, завершает SD-read её драйвером и
проверяет освобождение шины перед W5100. Принудительного снятия CS SD нет;
нарушение владения шиной фиксируется как `bus_fault=1` и даёт FAIL.
W5100 возвращён на исходные 4 МГц; SD init=250 кГц, SD data=4 МГц.
Все прежние аппаратные PASS и FAIL сохранены. Оператор подтвердил v0.4:
AVR 1.8.8 / SD 1.3.0 / 14 422 B Flash / 1 052 B SRAM и загрузку на COM4.
Два FAIL не устанавливают причину и не доказывают неисправность карты.

**История v0.2: целостность данных PASS 15/15; повторный CARD_INIT FAIL.**
[Аппаратные результаты](RESULT_2026-10-10.md): прогон
`20261010-150739-TEST08-4E60244A` прошёл все проверки, включая три чтения с
правильными CRC, удаление файла и два совпадающих чтения RTR после SD.
Минимальная измеренная свободная SRAM — 940 B. Исходные v0.1 ETH_SPI_AFTER FAIL
и v0.2 CARD_INIT FAIL (CMD0 timeout) сохранены. Следующий диагностический шаг —
обычный повтор уже сообщил PASS (итоговый фрагмент, 278 ms). Позднее отдельная
проверка карты прошла 15/15 (`76CEC702`, 276 ms), но следующий прогон после новой
загрузки завершился CARD_INIT FAIL (`DC5F04E5`, CMD0 timeout). Все исходы сохранены;
причина и стабильность инициализации пока не установлены. Последующий запуск
без новой загрузки дал ETH_SPI_AFTER FAIL. Два прогона v0.4 также дали FAIL. Подготовлена отдельная проверка карты
через Windows, которая теперь прошла. Причины чтений W5100 остаются
неустановленными; отдельный SD_ONLY прогон на UNO теперь прошёл 13/13.
Подготовлен следующий этап программы
LAB-01B. TEST-07 сохраняет шесть аппаратных PASS; его DhcpOutage перенесён на
отдельный роутер. Результаты старой LAB-01 с SD 4GB не заменяют проверку этой платы.
Текущая прошивка проверяет SPI и файловую систему без сетевого обмена;
одновременный Ethernet + SD остаётся задачей TEST-09.

## Подготовка

Arduino UNO / ATmega328P, тот же синий W5100 Shield, UART 115200, COM4 или фактический
порт. Ethernet CS=D10, SD CS=D4, SPI через ICSP/UNO D11–D13. Нужна исправная microSD
с FAT16 или FAT32 и свободным местом. exFAT этим тестом не поддерживается.
Объём и формат запишите до запуска; весь объём носителя тест не проверяет.
Не форматируйте карту автоматически ради теста: сначала используйте уже
подготовленную подходящую карту. Вставить карту при отключённом питании UNO,
затем подключить USB. Во время прогона карту не извлекать.

Тест создаёт только `T08CHECK.BIN` в корне карты. Создание использует `O_EXCL`:
занятое имя приводит к FAIL, существующий файл не перезаписывается и не удаляется.
При полном успехе созданный файл удаляется и проверяется отсутствие имени.
После неудачи он может остаться для диагностики. Сначала сохраните/изучите его на
ПК; повторный прогон разрешён после освобождения этого имени. Остальные файлы,
таблицы разделов и формат карты специально не меняются. При неисправности
носителя или потере питания сохранность файловой системы тест гарантировать не может.

SD 1.3.0 использует `Sd2Card`, `SdVolume`, `SdFile` из своего low-level API.
Это позволяет получить тип карты, число блоков, FAT и явные статусы sync/close,
а также не использовать выделяющий память wrapper `File`. W5100 снимается с
SPI при каждой SD-операции. Его RTR-регистр проверяется с сохранением исходного
значения до и после работы с картой. Прерывания Ethernet не используются.

## Сборка и загрузка — PowerShell 7

Исправленная v0.4 находится в текущей ветке `feature/w5100-test09-ethernet-sd`,
основанной на TEST-08/TEST-07. Переход на старую ветку TEST-08 вернёт прежнюю версию.
Локальные изменения старых sketches не удалять.

```powershell
cd C:\GitHub\Arduino-UNO-Shields
git fetch origin
git switch feature/w5100-test09-ethernet-sd
git pull --ff-only
$test8 = ".\labs\01-W5100-Ethernet\TEST-08_microSD_Hardware"
arduino-cli lib install "SD@1.3.0"
& "$test8\Build-Test08.ps1" -UploadPort COM4
```

Helper компилирует `arduino:avr:uno`, проверяет фактически выбранные AVR
1.8.6/1.8.8 и SD 1.3.0, записывает `build/TEST08/compile.json` и
`build-summary.json`, измеряет Flash/SRAM и SHA256 исходников/HEX. Загрузка
выполняется только после build gate и использует измеренный HEX.

Эквивалентная команда компиляции без загрузки:

```powershell
arduino-cli compile --fqbn arduino:avr:uno --warnings all `
    --build-path .\build\TEST08 $test8
```

Для сертифицирующего прогона всё равно нужен `build-summary.json`, создаваемый
helper. Build gate: Flash <=29 000/32 256 B, static SRAM <=1200/2048 B.
Текущая локальная сборка firmware 0.4, AVR 1.8.6/SD 1.3.0: **14 422 B / 1 052 B**.
Предыдущая v0.3 занимала **14 142 B / 1 050 B**; оператор подтвердил её
сборку/загрузку на AVR 1.8.8 с теми же размерами.
Предыдущая v0.2 локально занимала **14 134 B / 1 050 B**.
Для прежней firmware 0.1 оператор подтвердил AVR 1.8.8: **13 848 B / 1 050 B**
и успешную загрузку на COM4. Теперь оператор также подтвердил обе сборки/загрузки
firmware 0.2 на AVR 1.8.8: **14 134 B / 1 050 B**. Полные build-summary.json и
хеши бинарников для этих прогонов пока не предоставлены.
Компиляция не является аппаратным PASS.

## Один автоматический прогон

Закройте Serial Monitor. Скрипт сам откроет COM, дождётся BOOT/READY и пошлёт
`RUN` с уникальным токеном. Нажимать клавиши и оценивать время вручную не нужно.
Открытие COM с DTR=true может сбросить UNO; ожидается ровно один BOOT.
Текущий runner ожидает firmware `0.4` и `eth_spi_hz=4000000`. После обновления исходников повторить
Build-Test08 с загрузкой; старую прошивку runner отвергает до команды RUN.
Прошивка выдаёт отдельный перевод строки перед BOOT, чтобы начальные байты
не склеивались с баннером. Склеенный или повторный BOOT по-прежнему даёт FAIL.

```powershell
& "$test8\Test-MicroSDHardware.ps1" -SerialPort COM4 -DurationSeconds 90
```

90 s — предельное время ожидания, не обязательная длительность нагрузки.
После терминального результата платы скрипт завершает проверку сразу.
Вызовы SD синхронные: deadline ограничивает host-проверку, он не является
сторожевым таймером для зависшего MCU. Если плата не отвечает, итог FAIL.
Завершение COM и запись файлов могут добавить небольшое время к deadline.

## Этапы и критерии

### Текущий порядок и контроль ошибок

В SD 1.3.0 code=1/data=255 означает таймаут CMD0 с последним ответом FF;
он возникает до FAT и создания файла. В последней v0.3 ошибка воспроизвелась
при W5100 SPI=1 МГц. Это не проверило сохранность RTR после SD на 1 МГц.
Предложенный холодный запуск v0.3 не выполнялся: оператор остановил подбор
условий и потребовал проверить алгоритм. Ранее выполненный холодный PASS v0.2
остаётся отдельным историческим результатом, а не решением текущего отказа.

v0.4: сначала CS-уровни HIGH, затем OUTPUT и SPI.begin; далее CARD_INIT и
только после успешного перехода карты в SPI — ETH_SPI_BEFORE. Индексы первых
двух CHECK изменены: CARD_INIT=1, ETH_SPI_BEFORE=2. Остальные 13 этапов прежние.
Исходный RTR проверяется на согласованность/ненулевое значение до любой пробной
записи и восстановления. Перед W5100 вызов card.readEnd завершает возможный
частичный SD-read, затем проверяются оба CS, выдаётся idle-byte при обоих HIGH,
заканчивается handoff-транзакция и начинается отдельная транзакция W5100.
При занятой шине CS не поднимается насильно; fault защёлкивается и итог FAIL.
Закрытие корня входит в cleanup gate; ошибки финального close учитываются.
После bus fault новых SPI-операций для cleanup или диагностики не выполняется.

Эти команды остаются воспроизводимыми командами теста UNO. Два фактических
прогона v0.4 завершились FAIL до файловых операций; исходные консоли сохранены.
Отдельный USB-SD прогон успешно выполнен и сохранён. Следующий шаг:
[W5100_COMPARE](diagnostics/W5100_Compare/) после фактического SD_ONLY PASS.
Обычный полный TEST-08 остаётся отдельным 15-проверочным тестом.

### Проверки прогона

| Проверка | Требуемый результат |
| --- | --- |
| CARD_INIT (1) | Инициализация SD на D4 до любых обращений к W5100 |
| ETH_SPI_BEFORE (2) | Два согласованных валидных чтения RTR до write/read 0x1234 и восстановления |
| CARD_INFO | SD1/SD2/SDHC, ненулевое число 512-байтных блоков |
| FAT_VOLUME | Успешный mount FAT16/FAT32 |
| ROOT_OPEN | Открыт корень файловой системы |
| EXCLUSIVE_CREATE | Создан новый T08CHECK.BIN без перезаписи существующего имени |
| WRITE_2048 | 2048 детерминированных бинарных байтов, все write/sync/close успешны |
| REOPEN_VERIFY_2048 | Повторное открытие, точная длина, побайтовая проверка, CRC16 и EOF |
| SEEK_BOUNDARIES | Позиции 0, 63, 64, 511, 512, 1023, 2047; точное позиционирование и байт |
| APPEND_64 | Добавлены 64 байта; размер стал 2112, sync/close успешны |
| REOPEN_VERIFY_2112 | Весь файл 2112 байт совпал с образцом, EOF |
| REMOUNT_VERIFY | Закрытие корня, сброс файлового cache, повторная инициализация/mount и точное чтение 2112 байт |
| REMOVE_TEST_FILE | Удалён созданный файл, повторное открытие не удалось, корень успешно закрыт |
| ETH_SPI_AFTER | Два чтения RTR после SD совпадают с сохранённым исходным значением |
| RAM | Выборочный min_free >=512 B; final_free >=initial_free−64 B |

Образец содержит все 256 значений байта; формула для позиции p:
`((p*73) XOR (p>>3) XOR 0xA5) AND 0xFF`. CRC16-CCITT с начальным FFFF и полиномом
1021: **A535 для 2048 B, 2B28 для 2112 B**. Host вычисляет эти CRC независимо от
переданного результата. Нужны все 15 CHECK в порядке, каждый PASS, три точных
VERIFY, один правильный BOOT, READY, START и RESULT с токеном текущего запуска.
Дополнительно требуются две строки ETH_RTR (BEFORE/AFTER), согласованные probe,
restore и два точных RTR-чтения после SD. Перед выбором W5100 прошивка передаёт
FF при обоих CS=HIGH после завершения драйвера SD; проверка сохранности
регистра остаётся строгой. Дополнительно RESULT обязан содержать bus_fault=0.
Отсутствие этапа, неверные CRC/длина, другой токен, reset, low SRAM или timeout
дают FAIL. Источники firmware/module/runner должны совпадать с отчётом сборки.

Скрипт создаёт `runs/<date>-TEST08-<token>/serial.log` и `summary.json`:
UTC и UART, причины результата, тип/ёмкость/FAT, размеры, CRC, uptime теста,
выборочная SRAM, source/HEX hashes и build gate. Прошивка также пишет время
write; это диагностическое число, а не сертификация скорости всей карты.
Показываемая ёмкость вычисляется как число блоков ×512, без проверки каждого блока.

## Границы результата и разработка

Будущий аппаратный PASS применим только к проверенным UNO, Shield и карте. Remount
проверяет повторное открытие без файлового cache, но не сохранность при физическом
обесточивании. Нет теста hot-swap, power-cut, полного объёма, ресурса записи или
одновременного Ethernet/SD. SRAM измеряется в заданных точках приложения;
пиковый стек внутри библиотеки этими показаниями не определяется.

[Проверки разработки](VALIDATION_2026-10-10.md) отделены от аппаратного
результата. Host gates можно воспроизвести без UNO:

```powershell
& "$test8\tests\Test-HostGates.ps1"
```

Модель переключения общей SPI-шины компилирует реальные helpers прошивки:
`python tests/test_spi_release.py` из каталога теста; требуется Python и g++.
Она проверяет реальные helpers TEST-08/09: порядок CS, завершение частичного
чтения, отказ при занятой шине, idle-clocks и сохранение ошибочного первого
прочитанного байта. Физическая плата и аналоговые сигналы не моделируются.

Исходники используемой реализации:
[SD 1.3.0](https://github.com/arduino-libraries/SD/tree/1.3.0),
[SdFat API](https://github.com/arduino-libraries/SD/blob/1.3.0/src/utility/SdFat.h).
Диагностика CARD_INIT FAIL использует `CARD error_code/error_data`;
CARD_INIT PASS с FAT_VOLUME FAIL требует проверки раздела/формата на ПК.
