## Repair prepared for a new hardware run

Source review identified a missing shared-bus handoff in the sketch: after SD
operations, the raw Ethernet helpers selected W5100 without first clocking an
idle byte while both D4 and D10 were HIGH. Arduino SD 1.3.0 `chipSelectHigh()`
deselects the card and ends its SPI transaction without this extra byte.
The upstream SdFat `spiStop()` clocks FF after deselection; this supports the
handoff repair, but does not establish the cause of this particular shield's FAIL.

Firmware **0.2** adds the idle byte before every W5100 selection, logs two actual
RTR readings plus the expected value after SD, and records the initial probe/restore.
There is no retry until success, W5100 reset, post-SD RTR rewrite or relaxed
preservation criterion. A blank line separates startup bytes from the BOOT banner.
Host **0.2** still requires exactly one correctly framed BOOT, all 15 checks and
matching RTR diagnostics; it rejects old firmware before sending RUN.

Development validation: actual new AVR 1.8.6 compilation passes at 14,134 B Flash /
1,050 B static SRAM; 29 host verdict cases pass. A compiled peripheral model
using the actual sketch's SPI helpers passes v0.2 and rejects v0.1 under its
declared SD-MISO-release condition. These are development results, not hardware proof.
