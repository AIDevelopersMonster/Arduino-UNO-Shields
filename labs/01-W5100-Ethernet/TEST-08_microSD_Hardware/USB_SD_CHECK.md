# microSD через USB-картридер — отдельная проверка Windows

Оператор выбрал эту процедуру после двух TEST-08 v0.4 ETH_SPI_BEFORE FAIL.
Windows сообщил USB-диск №2 Generic STORAGE DEVICE, 3,75 GiB, раздел F: FAT32,
HealthStatus=Healthy. Это метаданные, а не результат записи/чтения.
**Аппаратный результат USB-SD пока PENDING. Прошивка UNO остаётся v0.4.**

В PowerShell 7 из C:\GitHub\Arduino-UNO-Shields:

```powershell
git pull --ff-only
$test8 = ".\labs\01-W5100-Ethernet\TEST-08_microSD_Hardware"
pwsh -NoProfile -File "$test8\Test-UsbSdCard.ps1" -DriveLetter F -ExpectedDiskNumber 2
```

Скрипт использует Get-Partition для проверки связи F: с USB-диском №2 и
проверяет FAT16/FAT32, доступность записи и свободное место. Перед записью
объясняет процедуру и ждёт Enter. Затем:

1. Создаёт уникальный USBSD_<token>.BIN через FileMode.CreateNew. Уже существующий
   файл открыть для записи нельзя. Пишет 16 MiB псевдослучайных байтов блоками
   64 KiB, использует WriteThrough и Flush(true), закрывает файл.
2. Заново открывает файл, проверяет точную длину, каждый байт, EOF и SHA-256.
3. Закрывает все файлы карты и просит выполнить Безопасное извлечение в Windows,
   отключить USB-картридер и нажать Enter, пока он отключён. Проверяет отсутствие
   смонтированного тома с прежним UniqueId.
4. Просит подключить тот же картридер с той же картой и нажать Enter после
   появления диска. Находит том по прежнему UniqueId, размеру, файловой системе
   и серийному номеру устройства; новая буква определяется автоматически.
5. Читает тот же файл и повторяет проверку каждого байта, длины, EOF и SHA-256.
   После полного успеха удаляет только созданный тестовый файл.

**PASS:** все три файловые фазы успешны, оба SHA-256 совпадают с записанным
образцом, отключение наблюдалось, идентичность тома подтверждена, cleanup выполнен.
**FAIL:** ошибка открытия/записи/сброса/чтения, расхождение байтов/длины/хеша,
превышение бюджета фазы, неподтверждённое отключение/другой том или ошибка cleanup.
Пройденные этапы и итог PASS зелёные; итог FAIL и причина красные. При неудаче
созданный файл сохраняется для диагностики; к иной карте скрипт не обращается.

runs/<date>-USBSD-<token>/console.log и summary.json находятся в репозитории
на ПК. JSON содержит метаданные тома, размер, seed, хеши, время файловых фаз,
стадию отказа, cleanup и SHA-256 исходников. Частичный summary сохраняется перед
операторским отключением; окончательный — после результата.

По умолчанию каждая файловая фаза имеет бюджет 60 s. Проверка времени происходит
между синхронными вызовами и после завершения: это кооперативный предел, не
принудительное прерывание зависшего драйвера Windows. Ожидания Enter в этот
бюджет не входят. Объём ограничен 16 MiB, а не всей ёмкостью карты.

Успех подтверждает данный файл через конкретный картридер/Windows после
наблюдаемого переподключения. Это не полная проверка поверхности, заявленной
ёмкости, долговременного хранения или общей SPI-шины UNO/W5100. Немедленное
чтение само по себе может быть обслужено кэшем; поэтому для итогового PASS
обязательно второе чтение после переподключения.

## Проверки разработки

PowerShell 7.5.2/Linux: оба новых .ps1 разобраны парсером; фактический C# helper
скомпилирован через Add-Type. 11 локальных случаев проверяют длины 1/65535/65536/
65537/16777216 B, совпадение с независимым Get-FileHash, отказ без перезаписи
занятого имени, другой seed, испорченный байт на границе блока, усечение,
лишние байты и истёкший бюджет. Это разработческие проверки временного файла,
не аппаратный USB-SD PASS. Windows Storage cmdlets и физическое извлечение
требуют фактического запуска оператором.

```powershell
pwsh -NoProfile -File "$test8\tests\Test-UsbFileCore.ps1"
```

Первичные API:
[FileMode.CreateNew](https://learn.microsoft.com/en-us/dotnet/api/system.io.filemode),
[FileStream.Flush(Boolean)](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush).
