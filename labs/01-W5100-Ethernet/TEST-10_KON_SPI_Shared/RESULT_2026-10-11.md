# TEST-10 — KON_SPI_Shared transition result

**Date:** 2026-10-11  
**Hardware:** Arduino UNO + blue W5100 Ethernet Shield + microSD  
**Library:** KON_SPI_Shared v0.1  
**Result:** **DIRECTIONAL PARTIAL PASS**

## Actual operator sequence

Boot:
- KON TEST-10 / SHARED SPI RECOVERY
- SD OFF, LAN OFF

### SD -> LAN
- `S1`: prepareSD PASS
- `SD.begin(4)`: PASS

- `L1`: prepareLAN PASS

### LAN -> SD
Immediately after the successful LAN phase:
- `S1`: prepareSD PASS
- `SD.begin(4)`: FAIL

Additional attempt:
- `R`: raw W5100 software reset PASS
- `L0`: LAN release DONE
- `S1`: prepareSD PASS
- `SD.begin(4)`: FAIL

**Transition LAN -> SD: FAIL.**

## Interpretation boundaries

The result proves directional asymmetry in this hardware/configuration:
- SD can be released sufficiently for W5100/DHCP to operate.
- After W5100 has operated, the SD card cannot be reinitialized by the stock SD library even after CS parking, release clocks, UDP stop, and W5100 MR software reset.

This does **not yet prove** that W5100 MISO remains electrically driven. Static CS HIGH states do not establish MISO high-impedance at the chip. It also does not prove a general W5100 defect.

The next diagnostic target is the physical shared MISO line after LAN use. Manual external reset previously restored the ability to use SD; unlike W5100 MR software reset, the shield reset circuit can assert the W5100 hardware /RESET input.

## Decision

KON_SPI_Shared v0.1 is retained because it establishes a successful SD -> LAN handoff. v0.2 should add a bounded MISO-release diagnostic before any deeper fork of SD/Ethernet.
