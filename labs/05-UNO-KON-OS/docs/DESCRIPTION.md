# KON-OS 0.1 — описание системы

## 1. Назначение

KON-OS 0.1 — экспериментальная малоресурсная операционная среда для
Arduino UNO R3 / ATmega328P, спроектированная специально под ограничения
32 KB Flash и 2 KB SRAM.

Текущая версия не является POSIX-совместимой или защищённой многозадачной ОС.
Это резидентное ядро-прототип с кооперативным диспетчером, системной оболочкой
и файловыми сервисами microSD.

Главная инженерная цель — отделить системные сервисы от прикладной логики и
проверить, насколько далеко можно развить модель ранних малых компьютеров на
современной 8-битной AVR-платформе.

## 2. Аппаратная платформа

- Arduino UNO R3 / ATmega328P;
- 16 MHz;
- 32 KB Flash;
- 2 KB SRAM;
- MAR2406 2.4-inch TFT Touch Shield;
- microSD:
  - CS = D10;
  - MOSI = D11;
  - MISO = D12;
  - SCK = D13.

В TEST-01 используются Serial и microSD. TFT и Touch в ядро 0.1 пока не
включены.

## 4. Архитектура

```text
+--------------------------------+
|          SERIAL SHELL          |
| HELP DIR TYPE WRITE MEM PS ... |
+--------------------------------+
|       COOPERATIVE KERNEL       |
| task table | timers | dispatch |
+--------------------------------+
|        DEVICE SERVICES         |
|        Serial | SPI | SD       |
+--------------------------------+
|       ATmega328P / UNO         |
+--------------------------------+
```

### 4.1. Резидентное ядро

Ядро постоянно находится во Flash и выполняет:

- инициализацию системы;
- кооперативное планирование;
- обработку команд оболочки;
- диагностику памяти;
- системное время;
- доступ к файловой системе microSD.

### 4.2. Кооперативный диспетчер

Каждая задача содержит:

- указатель на функцию;
- период запуска;
- время следующего запуска;
- счётчик запусков;
- флаг разрешения.

Текущие задачи:

```text
ID  TASK      PERIOD
0   SERIAL    1 ms
1   CLOCK     100 ms
```

Задачи используют один обычный AVR stack. Отдельные стеки, как в FreeRTOS,
не выделяются.

### 4.3. Системная оболочка

Командная строка работает по USB Serial на 115200 8N1.

Приглашение:

```text
A:/>
```

Команды нечувствительны к регистру в имени команды:

```text
DIR /
dir /
LS /
ls /
```

Аргументы после имени команды не переводятся в верхний регистр.

### 4.4. Файловая система

KON-OS 0.1 использует библиотеку Arduino SD и предоставляет файловые операции
как системные команды:

- монтирование;
- просмотр каталога;
- чтение текста;
- создание/перезапись;
- добавление текста;
- удаление;
- создание и удаление каталогов.

## 5. Чем KON-OS отличается от обычного скетча

Обычный Arduino sketch обычно является одной законченной программой. KON-OS
строится как постоянная системная среда, владеющая ресурсами машины и
предоставляющая повторно используемые сервисы.

Ключевая граница проекта:

```text
ordinary sketch:
  setup -> loop -> one application

KON-OS target:
  resident kernel
       |
       +-- system services
       +-- scheduler
       +-- shell
       +-- filesystem
       +-- application interface
               |
               +-- external apps/data
```

В версии 0.1 внешний исполняемый формат ещё отсутствует. Поэтому корректное
наименование текущего состояния: **operating environment / kernel prototype**.

## 6. Проверенный функционал TEST-01

На физическом Arduino UNO подтверждены:

- загрузка ядра;
- монтирование microSD;
- HELP;
- INFO;
- MEM;
- PS;
- UPTIME;
- DIR / LS;
- WRITE;
- TYPE / CAT;
- APPEND;
- MKDIR;
- RMDIR;
- DEL / RM;
- повторные операции без reset и повреждения файлов.

## 7. Дальнейшая архитектура

План развития:

```text
KON-OS 0.1  kernel + shell + SD       PASS
KON-OS 0.2  minimal TFT driver
KON-OS 0.3  Touch + file browser
KON-OS 0.4  external APP / bytecode
KON-Boot    SD -> native image -> Flash
```

KON-OS APP и KON-Boot — два разных режима:

- APP/bytecode остаётся на SD и выполняется резидентным ядром;
- native BIN копируется из SD во Flash и запускается после перезагрузки.

## 8. Ограничения версии 0.1

- нет memory protection;
- нет privilege separation;
- нет virtual memory;
- нет process isolation;
- нет preemptive multitasking;
- нет внешнего ABI приложений;
- нет RUN/LOAD/STOP;
- TFT/Touch пока не являются системными сервисами;
- команда WRITE/APPEND записывает одну строку за вызов;
- длина входной командной строки ограничена 87 символами плюс завершающий ноль.
