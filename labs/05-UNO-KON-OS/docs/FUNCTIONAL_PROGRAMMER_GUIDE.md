# KON-OS 0.1 — руководство функционального программиста

## 1. Для кого этот документ

Функциональный программист добавляет в KON-OS новые команды, сервисные функции
и прикладное поведение, не меняя фундаментальную механику ядра.

Важно: в версии 0.1 ещё нет внешнего формата приложений и команды RUN.
Поэтому функциональное расширение пока компилируется вместе с ядром.

Планируемая модель `.APP` / bytecode будет отдельным этапом KON-OS 0.4.

## 2. Модель программирования 0.1

Есть два допустимых типа расширений:

1. **Shell command** — действие запускается пользователем.
2. **Cooperative service task** — небольшой периодический сервис.

Примеры:

```text
CALC 2+2
DATE
SENSOR
LOG
VIEW /FILE.TXT
```

## 3. Добавление команды

Пример команды ECHO.

### Handler

```cpp
static void cmdEcho(char *args) {
  Serial.println(args);
}
```

### Dispatch

В `executeCommand()`:

```cpp
} else if (strcmp(line, "ECHO") == 0) {
  cmdEcho(args);
```

### HELP

В `cmdHelp()`:

```cpp
Serial.println(F("ECHO <text>       print text"));
```

## 4. Синтаксис аргументов

Parser разделяет только имя команды и остаток строки.

Например:

```text
WRITE /TEST.TXT HELLO WORLD
```

handler получает:

```text
/TEST.TXT HELLO WORLD
```

Если команде требуется несколько аргументов, их нужно разобрать внутри
handler без динамической памяти.

Рекомендуемый способ — перемещать указатели и временно заменять delimiter на
нулевой байт.

## 5. Ограничение длины команды

Вся строка должна помещаться в 87 символов.

Поэтому прикладная команда не должна предполагать длинные JSON, base64 или
другие многословные форматы.

Для больших данных следует использовать файл на SD.

## 6. Файлы как прикладной интерфейс

Текущая версия уже позволяет прикладному коду использовать SD как постоянное
хранилище:

```text
/DATA
/CONFIG
/APP
```

Рекомендуемые свойства данных для AVR:

- ASCII/compact binary;
- короткие имена;
- чтение потоково;
- не загружать весь файл в RAM;
- не создавать большие parser trees;
- не использовать heap.

## 7. Периодическая прикладная функция

Если логика должна работать постоянно, её можно оформить как cooperative task.

Пример:

```cpp
static void taskSensor() {
  if (!sensorDue()) return;
  readOneSample();
}
```

Правила:

- одна активация — один небольшой квант работы;
- никаких `delay()` на сотни миллисекунд;
- никаких бесконечных внутренних loops;
- длинную процедуру разбивать на state machine.

## 8. State machine вместо блокировки

Не так:

```cpp
doWholeOperation();
```

Лучше:

```cpp
switch (state) {
  case STEP_OPEN: ...
  case STEP_READ: ...
  case STEP_PROCESS: ...
  case STEP_CLOSE: ...
}
```

Каждый вызов выполняет один шаг и возвращает управление ядру.

## 9. Использование Serial

Serial является системным ресурсом. В 0.1 отдельного API-слоя ещё нет, поэтому
команды используют Arduino Serial непосредственно.

Для будущей совместимости желательно:

- не менять baud rate;
- не печатать бинарные данные без отдельного режима протокола;
- завершать ответы newline;
- использовать короткие стабильные ответы;
- системные ошибки начинать с `ERR`.

## 10. Использование SD

Перед операцией проверять готовность SD.

Прикладная функция должна:

- открыть файл;
- выполнить минимальный объём работы;
- закрыть файл;
- вернуть управление.

Не следует держать несколько файлов открытыми без необходимости.

## 11. Будущий Application ABI

Планируемый KON-OS 0.4 должен отделить приложения от Flash ядра.

Целевая модель:

```text
RUN /APPS/DEMO.APP
      |
      v
loader / VM
      |
      +-- console service
      +-- filesystem service
      +-- timer service
      +-- graphics service
      +-- input service
      |
EXIT -> shell
```

До появления этого ABI никакой compiled-in handler не следует называть
внешним KON-OS приложением.

## 12. Требования к функциональному расширению

Перед merge:

- sketch компилируется для `arduino:avr:uno`;
- записаны Flash/SRAM показатели;
- MEM не показывает опасного падения runtime reserve;
- DIR/TYPE/WRITE после изменения продолжают работать;
- scheduler counters в PS увеличиваются;
- нет зависания остальных задач;
- документация команды обновлена.
