# LAB-05 / TEST-08 — KAP2 multi-label named control flow

## Goal

Remove the main KonSol 0.5 KAP2 control-flow limitation: one active MARK target.

TEST-08 keeps the KAP2 file header and existing KAP1/KAP2 programs compatible,
but adds indexed labels and named source-level branches.

## Firmware

`sketches/06_KonSol_KAP2_MultiLabel/06_KonSol_KAP2_MultiLabel.ino`

Version: **KonSol 0.6**

The resident VM supports up to eight indexed KAP2 labels.

## New KAP2 extension

| Opcode | Encoding | Meaning |
| --- | --- | --- |
| `4A` | `4A ii` | LABEL id |
| `4B` | `4B ii` | unconditional JMP label |
| `4C` | `4C ii` | JZ label |
| `4D` | `4D ii` | JNZ label |

Legacy opcodes remain valid:

```text
44      MARK
45      JNZ MARK
49      JZ MARK
```

Existing COUNTER.KAP from KonSol 0.5 must therefore continue to run unchanged.

## Label indexing model

Human-readable names exist in KASM source:

```text
LABEL LOOP
JZ RED_STATE
JZ YELLOW_STATE
JMP GREEN_STATE
```

KASM maps those names to compact label IDs 0..7.

At application start, KonSol scans the KAP2 stream once, records each label ID
and its raw microSD file position, then rewinds to the first instruction.

Runtime branch operations therefore perform direct SD `seek()` to the indexed
position instead of rescanning the whole file.

Memory cost is intentionally bounded:

```text
8 x uint16_t label positions = 16 B
1 x label bit mask           = 1 B
----------------------------------
persistent label table       = 17 B
```

KAP2 multi-label files are limited to 65535 raw ASCII-file bytes in this
implementation so label positions remain 16-bit.

## Test application

Readable source:

`apps/KAP2/MULTILABEL.kasm`

Generated bytecode:

`apps/KAP2/MULTI.KAP`

The application implements three independent branch destinations:

```text
LOOP
RED_STATE
YELLOW_STATE
GREEN_STATE
```

Flow:

```text
touch #1 -> R0=1 -> JZ RED_STATE
           RED -> JMP LOOP

touch #2 -> R0=2 -> JZ YELLOW_STATE
           YELLOW -> JMP LOOP

touch #3 -> R0=3 -> neither JZ matches
           JMP GREEN_STATE
           GREEN -> WAIT_TOUCH -> EXIT
```

This deliberately exercises both conditional and unconditional named branches.

## KASM build

From repository root:

```powershell
python .\tools\kasm\kasm.py `
  .\labs\05-UNO-KON-OS\apps\KAP2\MULTILABEL.kasm `
  -o .\MULTI.generated.KAP
```

Expected:

```text
KASM PASS: KAP2 -> MULTI.generated.KAP
Instructions/records: 35
```

Then compare:

```powershell
$A = (Get-Content -Raw .\MULTI.generated.KAP).Replace("`r","").Trim()
$B = (Get-Content -Raw .\labs\05-UNO-KON-OS\apps\KAP2\MULTI.KAP).Replace("`r","").Trim()
$A -eq $B
```

Expected:

```text
True
```

## Firmware build

```powershell
arduino-cli compile --fqbn arduino:avr:uno `
  .\labs\05-UNO-KON-OS\sketches\06_KonSol_KAP2_MultiLabel
```

Observed build result:

```text
Flash: 27568 / 32256 bytes (85%)
SRAM globals: 1256 / 2048 bytes (61%)
Linker-reported SRAM remaining: 792 bytes
```

Compared with KonSol 0.5:

```text
KonSol 0.5
Flash: 26798 B
Globals: 1239 B

KonSol 0.6
Flash: 27568 B
Globals: 1256 B

Delta:
+770 B Flash
+17 B global SRAM
```

Compile-time Flash headroom:

```text
32256 - 27568 = 4688 B
```

The +17 B global-SRAM delta exactly matches the planned persistent multi-label
table:

```text
8 x uint16_t label positions = 16 B
1 x label mask               =  1 B
----------------------------------
total                        = 17 B
```

Status: **BUILD PASS / READY FOR UPLOAD AND PHYSICAL TEST**.

## Physical execution

Upload KonSol 0.6 and run:

```text
INFO
MEM
RUN /MULTI.KAP
```

Expected Serial:

```text
APP RUN /MULTI.KAP
MULTILABEL KAP2
```

Expected TFT sequence:

```text
MULTI LABEL
TOUCH 3X

touch 1:
RED
STEP 1
TOUCH NEXT

touch 2:
YELLOW
STEP 2
TOUCH NEXT

touch 3:
GREEN
STEP 3
TOUCH TO EXIT
```

Final touch:

```text
APP EXIT 0
```

Then verify:

```text
APP
MEM
DIR /
```

## Backward-compatibility gate

On the same KonSol 0.6 firmware, run the old KonSol 0.5 application unchanged:

```text
RUN /COUNTER.KAP
```

It must still complete the five-touch legacy MARK loop and exit normally.

## PASS criteria

TEST-08 becomes FULL PHYSICAL PASS only when:

1. KonSol 0.6 compiles and boots.
2. KASM accepts multiple LABEL declarations.
3. Forward branches to labels declared later in the source assemble correctly.
4. MULTI.generated.KAP equals the repository reference.
5. RED_STATE is selected after touch 1.
6. YELLOW_STATE is selected after touch 2.
7. GREEN_STATE is selected after touch 3.
8. JMP LOOP returns from RED and YELLOW states.
9. final WAIT_TOUCH / EXIT returns with APP EXIT 0.
10. shell and SD remain usable.
11. no progressive free-RAM loss is observed.
12. legacy COUNTER.KAP still runs unchanged.
