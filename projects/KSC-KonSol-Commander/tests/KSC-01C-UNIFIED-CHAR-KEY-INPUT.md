# KSC-01C - Unified Character & Special-Key Input Model

Status: PHYSICAL FUNCTIONAL PASS

Date: 2026-10-08

Target:

- Arduino UNO / ATmega328P
- HY-M302
- USB Serial 115200
- KSC Raw TTY 0.2
- asynchronous NEC IR input

## Purpose

KSC-01C replaces the KSC-01B test-only model in which printable characters such
as digits, M, and P could be interpreted as logical control keys.

The new model separates input into two semantic classes:

```text
CHAR - printable character input
KEY  - navigation/control input
```

The physical source is preserved independently:

```text
SRC=TTY
SRC=IR
```

## Verified TTY semantics

Printable keyboard input remains character data:

```text
8 -> CHAR '8'
M -> CHAR 'M'
P -> CHAR 'P'
A -> CHAR 'A'
a -> CHAR 'a'
/ -> CHAR '/'
. -> CHAR '.'
```

Special PC keys generate control events:

```text
UP        -> KEY UP
DOWN      -> KEY DOWN
LEFT      -> KEY LEFT
RIGHT     -> KEY RIGHT
ENTER     -> KEY ENTER
BACKSPACE -> KEY BACK
ESC       -> KEY BACK
HOME      -> KEY HOME
F9        -> KEY MENU
F10       -> KEY POWER
END       -> KEY END
DELETE    -> KEY DELETE
```

The two consecutive BACK events in the captured log are expected because both
Backspace and Esc were tested.

## Verified IR semantics

IR digits are character data:

```text
IR 0 -> CHAR '0'
IR 5 -> CHAR '5'
IR 8 -> CHAR '8'
IR 9 -> CHAR '9'
```

IR navigation/control remains special-key input:

```text
IR UP     -> KEY UP
IR DOWN   -> KEY DOWN
IR LEFT   -> KEY LEFT
IR RIGHT  -> KEY RIGHT
IR OK     -> KEY ENTER
IR RETURN -> KEY BACK
IR HOME   -> KEY HOME
IR MENU   -> KEY MENU
IR POWER  -> KEY POWER
```

## Architectural result

The same logical semantic event can now be generated by different physical
sources without losing source identity:

```text
PC 8      -> SRC=TTY TYPE=CHAR CHAR='8'
IR 8      -> SRC=IR  TYPE=CHAR CHAR='8'

PC UP     -> SRC=TTY TYPE=KEY KEY=UP
IR UP     -> SRC=IR  TYPE=KEY KEY=UP

PC F9     -> SRC=TTY TYPE=KEY KEY=MENU
IR MENU   -> SRC=IR  TYPE=KEY KEY=MENU

PC F10    -> SRC=TTY TYPE=KEY KEY=POWER
IR POWER  -> SRC=IR  TYPE=KEY KEY=POWER
```

This resolves the ambiguity identified after KSC-01B: printable terminal bytes
are no longer consumed as control commands.

The model is suitable as the common input foundation for both a command-line
shell and the future KonSol Commander UI.
