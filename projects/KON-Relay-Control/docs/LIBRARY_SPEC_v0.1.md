# KON_RelayShield — техническое задание v0.1 (Stage 01)

**Артефакт: DESIGN / NOT IMPLEMENTED.** Цель: обычная Arduino-библиотека управления четырьмя механическими реле на UNO R3, независимая от KonSol, Modbus, Bluetooth, KSC и Serial.

## 1. Границы

- Библиотека обслуживает **4 физических GPIO**, известные пользователю по результату аудита.
- Она управляет **командуемым состоянием** катушек, не утверждая фактическое положение сухих контактов.
- В библиотеке **нет** командного интерфейса, протокольной авторизации, хранения файлов, сетевых функций и PLC-сценариев.
- Работоспособность на ATmega328P (AVR, 16 МГц, 2 КБ SRAM) — обязательная цель компиляции и измерения ресурсов.

## 2. Требуемые настройки

`RelayConfig{uint8_t pins[4], bool activeHigh}`. Значения не считать измеренными до HWA-01G. Защита от повторяющихся GPIO и невалидных номеров каналов. В библиотеке не закреплять D4..D7 навсегда. Каналы нумеруются для пользователя 1..4.

## 3. Предлагаемый API (к утверждению в этапе 02)

```cpp
struct RelayConfig {
  uint8_t pins[4];
  bool activeHigh;
};
class KON_RelayShield {
public:
  bool begin(const RelayConfig& cfg);
  bool set(uint8_t channel1to4, bool on);
  bool on(uint8_t channel1to4);
  bool off(uint8_t channel1to4);
  void allOff();
  bool pulse(uint8_t channel1to4, uint32_t durationMs, uint32_t nowMs);
  void update(uint32_t nowMs);
  bool commanded(uint8_t channel1to4, bool& result) const;
};
```

`begin()` обязан устанавливать логический OFF для всех четырёх каналов перед переводом соответствующего GPIO в OUTPUT. Но гарантии состояния **до начала setup/begin, во время RESET, отключения питания и при отказе электроники не даются**.

`pulse()` использует `millis()` и требует регулярного `update()`; максимальная длительность ограничена (для v0.1 предлагается 3 600 000 мс), никаких блокирующих `delay()`.

Повторный `set(ON)` при уже включенном выходе идемпотентен. Вызовы `set(OFF)` и `allOff()` отменяют запланированный импульс. Переопределение поведения pulse-on-active — отдельно документировать; по умолчанию запуск нового импульса заменяет прежний таймер.

## 4. Нефункциональные требования

- Запрет `malloc/free/new`, STL-динамики и Arduino `String` в драйвере; фиксированные массивы на четыре канала.
- Без обязательных внешних зависимостей, Wire, SD, SoftwareSerial, дисплея.
- Отсутствие вызовов `Serial.print` внутри драйвера.
- Простой пример `01_BlinkRelay`, пример неблокирующего импульса `02_PulseNonBlocking`, пример `03_SerialControl` (только приложение).
- Везде таблица CH→PIN, политика уровня OFF и заметные предупреждения об отсутствии аппаратной обратной связи.
- Сборка через Arduino IDE 1.8.19 и `arduino-cli --fqbn arduino:avr:uno`.
- `library.properties`, `src/KON_RelayShield.h/.cpp`, `examples/`, `keywords.txt`, `LICENSE` после утверждения API.
- Метрики сборки: Flash, SRAM globals, скомпилированный бинарник/версия core, используемые таймеры и ссылки на воспроизводимые скетчи.

## 5. Контракт для KonSol, Modbus и PLC

Верхний слой *читает commanded*, вызывает `set/pulse/update`, решает приоритеты, проверяет тайм-ауты и права; драйвер не различает Modbus/USB/BLE. Если ядро прекращает обслуживать `update`, автоматическое выключение импульса более не гарантируется — требуется watchdog и физическая политика безопасности в отдельном слое.

Для Modbus нужно различать Coil = commanded state и возможные Discrete Inputs = измеренные сигналы. **Нельзя** маркировать значение commanded как подтверждённое состояние силового контакта.

## 6. Тесты приёмки библиотеки (этап 02)

- Драйвер не компилируется/отвергает недопустимую конфигурацию (по контракту выбранного API).
- Никакого автоматического включения реле при `begin` после подтверждённого ACTIVE_LEVEL.
- Каждая команда ON/OFF действует на один физически измеренный канал.
- `allOff` выключает все каналы и очищает импульсные таймеры.
- `pulse` корректен на границе переполнения `millis()`.
- Повторный `update` в том же моменте не меняет состояние.
- Проверены требуемые сборочные инструменты и размер памяти на целевой платформе.
- Аварийное состояние после RESET документируется **по эксперименту**, а не выводится из кода.

## 7. Не является целью v0.1

Открытая электрическая цепь NO/NC не подтверждается программно; сваривание контактов и аппаратная безопасность не обнаруживаются без дополнительных входов. Ни IEC 61131-3, ни промышленная сертификация не заявляются.

## 8. Gate

Реализация начинается после HWA-01D/G: известны реальные четыре pin, CH→PIN и активный уровень. До этого примеры с автопереключением реле не должны выпускаться как готовые.
